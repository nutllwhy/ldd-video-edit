# 铅笔素描本动画（SK 管线）

这是一套适合横竖屏的手绘动画管线：点阵纸 + 石墨线 + 手写字 + 一种重音色，画面轻松，像边讲边画。

和 `animation.md` 里 HyperFrames + House kit 那套的区别：这套**不依赖 HyperFrames**，一个镜头就是一个 html，Chrome 逐帧截图直接出 mp4，搭起来快、多个 Agent 并行不打架。新片子要做手绘，默认用这套。

## 1. 什么时候用
- 口播在讲**道理、趋势、步骤、关系**（预算往哪流、第几单之后变好走、谁跟谁匹配），没有真实素材能接住的句子
- 项目需要手绘、亲和、不那么严肃的表达
- 不适合：要展示真截图、真数字证据为主的段落 → B 资料拼贴（但素描本里可以 `SK.drop` 贴一张去过标识的截图当"剪报"）

## 2. 搭工程
```bash
export SK="$(pwd)"  # 在 skill 仓库根目录运行
$SK/scripts/new_sketch.sh <project>            # → <project>/anim/{kit,assets,renders,_chk,_ref} + BRIEF.md
cd <project>/anim
cp _ref/steps-climb.html m01-xxx.html          # 从参考镜头复制改
perl -e 'alarm 200; exec @ARGV' node $SK/scripts/sk_render.mjs m01-xxx.html _chk/m01 0.5,2,4   # 静帧
perl -e 'alarm 900; exec @ARGV' node $SK/scripts/sk_render.mjs m01-xxx.html renders/m01-xxx.mp4
```
依赖：`playwright-core`（渲染器会依次找 `$PLAYWRIGHT_DIR`、`$HYPERFRAMES_DIR`、当前目录、全局 npm）+ Playwright Chromium（或用 `CHROME` 指定浏览器可执行文件）。字体 `Hannotate SC`（macOS 自带手札体），换机器先 `fc-list | grep -i hannotate`。

## 4. 一个镜头的写法
```html
<script src="kit/gsap.min.js"></script><script src="kit/sk.js"></script>
<svg id="sv" width="1080" height="1920" viewBox="0 0 1080 1920"><g id="world"> …画面… </g></svg>
<script>
var D=6.3; SK.page(document.getElementById('sv'), {accent:'#07C160'});
var tl=gsap.timeline({paused:true}); SK.boil(tl,D);
var cam=SK.cam(tl,'#world',{cx:420,cy:820,s:1.22});
SK.write(tl,'.t1',0.05,0.45,0.3);          // 关键词出现前 0.1–0.2 s 开始写
…
SK.mount(tl,D);
</script>
```
- 所有东西放在 `#world` 里，镜头只动 `#world`
- 石墨线：`<g filter="url(#pencil)" stroke="#3E3C38" fill="none" stroke-linecap="round">`；手写字：`<g filter="url(#pen)">` 里的 `<text>`，每个字稍微 `rotate(-2~-3)`，别写得横平竖直
- 重音色**只用在 2–4 处**：关键词 `<tspan fill>`、圈（两个错开的椭圆叠一起，像画了两圈）、手画波浪下划线、勾、`url(#ghatch)` 排线、主角的帽子
- 只用时间轴驱动，不用 setTimeout / CSS animation（渲染器是 seek 的）
- 横屏：svg 改 `width="1440" height="1080"`，kit 会自动按画布算镜头中心和滤镜范围


## 4b. 人物：火柴人的画法（规则 A10）

> 火柴人是默认，不是唯一。别的画风、别的角色（色块小人、机器人、小动物）怎么画见 `references/sketch-styles.md`「人物和道具」。下面是火柴人的细则。
默认采用火柴人，作为简洁、可控的角色起点。照 `stick-sort.html` 写。想换角色或画风，见 `sketch-styles.md`。

**长相**
- 头：圆，r≈60（横屏 1920 宽）/ 按画布等比；填纸色 `#F6F3EA` 盖住后面的线，描边 7px 深色 + `filter="url(#pen)"`
- 脸上只有：两个小黑点眼（r≈7）、一道弧线嘴。表情就靠这三样变：眨眼（点变短弧）、惊讶（点放大 1.4 倍 + 嘴变 o）、开心（眼变 ∩ 弧 + 嘴张开）
- 身体：一条略弯的线，长≈头直径 ×1.6。**肩点在脖子下面约 30px**（头底下留一截脖子），别让胳膊直接从头底下长出来。腿被桌子挡住时不用画；站着时两条线腿，脚不画
- 胳膊：每只两段（上臂 + 前臂），用 IK 解出肘的位置，画成**折线 `M肩 L肘 L腕`，肘处倒一个 ~18px 的小圆角**，肘要看得见；末端一个实心小圆点当手（r≈9），不画手指。**不要用 `Q肘` 画成弧线**——控制点不在线上，整条胳膊变成一根面条（早期测试发现不自然）
- 主角可以戴一顶重音色小帽子；其他角色不戴。**不加头发、衣服、腮红、耳环、鼻子、眉毛**
- 情绪符号：头顶冒重音色「！」、头两侧四道短线（开心/得意）

**共用火柴人库 `kit/stick.js`**（`new_sketch.sh` 会拷进来）：`LDD.create('#层',{id,x,y,scale})` 建一个人，`actor.s` 上改 `lean/tilt/hop/lx/ly/blink/happy/wide/mo/L/R`，每帧 `actor.draw(t)`；`actor.hand('R')` 拿手的世界坐标给道具跟随；`LDD.label/LDD.write` 写手写字。库里已经处理好：折线胳膊、视线、错开的自动眨眼、**够不着时身体自动往那边探**（胳膊最多伸到约 86%，平滑、不跳）。新镜头优先用它，别自己再写一套骨架。

**手臂默认值（默认值）**：上下臂各 110、肩点 x=±14 并用短肩线连到身体；左肘分支 +1、右肘分支 −1，待机手位 L=(-70,20)、R=(70,20)。这些是当前默认骨架的起点，不保证任意目标姿势都自然。取物够不到时先移动身体或道具；可通过 `armLength` 和 `bendL/bendR` 适配具体动作，适配后仍做 A11 检查。

**视线要看得出来**：眼珠位移 `lx*19 / ly*13`（头半径 62 时），嘴跟着偏 `lx*13`。只挪 8px 在 4:3 小画面里等于一直盯着镜头，观众会觉得人"在盲操作"。拿东西前先 `lx/ly` 看过去，举起来看手里，放下看落点，最后才回正看镜头。

**怎么动**（`stick-sort.html` 里都有）
- 骨架：`ROOT`（髋，可以藏在桌子后）→ 身体 `rotate(lean)` → 头在脖子上 `rotate(tilt)`；肩点 = `bodyPt(x,y)`，随身体前倾一起动
- 胳膊长 `L1/L2` 先按"最远要够到哪"算好：肩到每个目标点的距离都要 < L1+L2，否则胳膊会被拉成一根直棍。够不着就把道具挪近或让身体前倾，别把胳膊加长到比身体还夸张
- 拿东西：手先到纸角 → `grip=1` 之后每帧把纸的锚点锁在手的位置；**手的图层在纸后面**，纸压在手前就是"捏住"，不用画拇指
- 松手：`grip=0` 那一帧纸从当前位置开始落（`fromTo` 从手的位置起，`immediateRender:false`），不能跳
- 时刻有一点活气：身体随呼吸上下 2px、每 2–3 秒眨一次眼、视线（眼珠位移 `lx/ly`）先看向要拿的东西再伸手
- 动作落点前 0.1–0.2 s 起手；跳起来用 `hop`，落地 `back.out` 小回弹只用在人物身上

**常见穿帮**（自检逐条看）
- 举起来的纸盖住头：举的位置往外放、身体往反方向靠一点（`lean` 负值），截静帧确认头和纸之间有空隙
- 胳膊从头前面穿过去：肩点在脖子两侧，目标在身体另一边时换另一只手
- 手和纸分开：`grip` 期间纸锚点必须每帧跟手，不能只在关键帧对齐
- 胳膊长短突变：L1/L2 全片固定，不同镜头也一样
- **胳膊伸成直棍**：目标点离肩超过两段长的 ~90% 就直了。用 `stick.js` 的自动前倾，或把道具挪近；自查时跑一遍每帧 `reach/limit`，>0.92 的帧要处理
- **道具凭空出现**：东西要从哪儿来就从哪儿来——发票从信封里往上冒（信封前片盖住 + clipPath 截掉信封底以下），照片从手机里滑出，本子开场就画在桌上。镜头中途用 `SK.show` 淡入一个被拿的东西 = 穿帮
- **结尾冻死**：别在 render 里写 `t=Math.min(t,D-.5)`，那会把铅笔颤动、呼吸、眨眼一起冻住，最后半秒像卡帧。动作在 D-0.5 前做完就行，时间照常走
- 所有人同一时刻眨眼：自动眨眼按角色 id 错开（库里已做）

## 4c. 手臂姿态检查（A11）

**手能碰到道具，不等于手臂自然。** 肩点过近、IK 肘分支朝内，或收手目标留在腰前，都可能让上臂与躯干长段重合、前臂在腰部横穿，看起来像手从腰上长出来。不能凭 `reach/limit` 较小、手物间距为零就判整个人物通过。

- 先在全画面里辨认肩→上臂→肘→前臂→手，再放大人物核对：肩部连接清楚，上臂不沿躯干重复画一长段；肘的折线朝向符合本次动作，不能向身体里反折。
- 自然待机和放下后的手要收回身体两侧，保留轻微弯肘。不要把双手都停在腰前的水平线上。刻意交叉、托举或支撑可以采用不同姿势，但要在镜头方案写明意图，不能用作默认待机姿势。
- 对伸手、接触、拿起、放下、收手分别截关键帧；同时检查放下后的最后半秒和末帧。每个可疑动作查看前后相邻帧，避免只修漂亮的单帧而留下肘部跳变。先改肩点、肘分支、手的目标或身体位置，不靠加长手臂掩盖问题。

运行几何辅助检查：

```bash
node "$SK/scripts/arm_pose_check.mjs" shot.html --out report.json
```

报告把 `geometry_status` 与 `needs_visual_review` 分开：几何检查只能发现它覆盖的异常；即使几何通过，仍要看人物局部和动作序列，再单独记录视觉结论。检查回归时也要纳入已知失败案例，确认能识别上臂压住躯干、肘内折、腰部横穿的问题；不能只凭手物贴合就判定通过。

## 5. 跟口播对时（最关键）
1. 每个镜头的时长 **D = 下一段开始 − 这段开始**，从字幕 cues 算，不是拍脑袋
2. 镜头清单里写出**关键词相对镜头开头的秒数**（例：「关键短句」@3.95），动作对准它，提前 0.1–0.2 s
3. 口播重录 / 改稿后复用旧镜头：
   - 时长差 ≤ 0.5 s：直接剪尾（末尾通常是停稳的全图）或靠拼接时 hold 末帧补
   - 差 10–20%：`ffmpeg -vf "setpts=PTS*新/旧"` 整体变速，手绘感不受影响
   - 删了内容 / 节奏全变：复制一份 html（如 `shot-02b.html`），删掉元素、按新关键词时间重排时间轴，旧版留着

## 6. 多个 Agent 并行
- 主 Agent 先亲手做**一个参考镜头**并通过 G2 审核，再按 `anim/BRIEF.md` 派活
- 每个 worker **4–5 个镜头**。6 个以上容易到轮数上限，停在半截（实测：一个 worker 做 5 个，第 5 个没出片就停了）
- BRIEF 的镜头清单里，每个镜头写：D、口播原句、关键词时间、画面、**允许出现的数字和专有名词**
- 同时只让每个 worker 跑一个 render；谁都不许 `pkill chrome`
- 机器负载高时 10 秒的镜头要渲近 10 分钟，alarm 给到 900

## 7. 自检
- 每个镜头：开头 / 关键动作 / 末帧前 0.1 s 截静帧，看重叠、出界、字被线穿过、字残缺
- 有角色的镜头另做 [4c 角色姿态检查](#4c-手臂姿态检查a11)：拿取与收手都要看，几何检查和视觉结论分开记录
- vision 对"贴着 / 压住"和坐标的判断**经常前后矛盾**：拿不准就量像素（PIL 读颜色找边界）或裁图放大
- 拼完以后整片每 4–5 秒抽一帧拼成联系表，再看一遍字幕有没有压到画面里的字
- 时长：`ffprobe` = D，误差 < 0.05 s

## 8. 踩过的坑
- **转写里的专有名词不能直接画上去**：不认识的产品名、模式名、功能名，先对照批准的口播稿并查证；无法核实则不画，或向项目负责人确认（规则 M7）
- **现场听来的内部数字不一定能公开**：先在 G1 方案中列出所有现场数据，逐项确认公开许可后再上画面（规则 M8）
- 重音色下划线贴着字：至少往下留 12px
- 小人的手势在缩小的静帧里认不出（竖大拇指像扶头）：拳头和拇指画大一点，往身体外伸
- **角色插画不要和程序绘制的肢体拼接**：媒材不一致容易让肢体显得割裂；需要动作的角色应采用同一媒材的矢量绘制和骨架（规则 A10）
- 一个元素滑入时会扫过别的字：改入场方向（从右下斜着进），全程量一下左边缘
- 竖屏下半部 y 1520 以下是字幕带，画面内容别往下放；内容太集中在中间又会显得空，用镜头推近补
- 截图贴进来之前先裁掉平台 logo、悬浮按钮、二维码弹窗
